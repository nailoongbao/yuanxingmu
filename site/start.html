01 / 首次安装

给这次工作一个独立目录。

下面以 Ubuntu 24.04 / WSL Ubuntu 24.04、x86_64 电脑为例。需要系统 Python 3.12+、Node.js 24.16.0、OpenClaw 2026.9.4 和 bubblewrap 0.9.0。其他环境需要另外验证；当前还需要在终端中完成安装。

Windows 用户：先打开 Ubuntu 终端

在 PowerShell 中运行下面的命令，按屏幕提示完成 WSL 安装，再打开 Ubuntu 24.04。后续命令都在 Ubuntu 中运行。已有合适环境可以跳过。

wsl --install -d Ubuntu-24.04

请按顺序一段一段执行，报错时先处理错误。工作目录放在 Linux 的 ~ 下。已经装好后，直接看日常打开与关闭。较长命令可左右滑动查看，“复制”会复制整段。

安装系统依赖

sudo apt-get update
sudo apt-get install -y python3 python3-venv git curl xz-utils ca-certificates bubblewrap
/usr/bin/python3 --version
bwrap --version

Python 应为 3.12 或更新版本。bubblewrap 已验证版本是 0.9.0，能否使用还要由后面的实际检查决定。

下载 Node.js

YXM_DIR="$HOME/yuanxingmu"
mkdir -p "$YXM_DIR/tools" "$YXM_DIR/openclaw" "$YXM_DIR/inputs"
cd "$YXM_DIR/tools"
curl --fail --location --output node-v24.16.0-linux-x64.tar.xz \
  https://nodejs.org/dist/v24.16.0/node-v24.16.0-linux-x64.tar.xz
curl --fail --location --output SHASUMS256.txt \
  https://nodejs.org/dist/v24.16.0/SHASUMS256.txt
sha256sum --check --ignore-missing SHASUMS256.txt
tar -xJf node-v24.16.0-linux-x64.tar.xz
export PATH="$YXM_DIR/tools/node-v24.16.0-linux-x64/bin:$PATH"
node --version

文件校验应显示 OK，Node 版本应为 v24.16.0。这里下载的是 Linux x86_64 版本，ARM 电脑不能直接使用这个压缩包。

安装元星木和 OpenClaw

git clone https://github.com/yh-l20/agent-defense-check.git "$YXM_DIR/agent-defense-check"
/usr/bin/python3 -m venv "$YXM_DIR/.venv"
"$YXM_DIR/.venv/bin/python" -m pip install "$YXM_DIR/agent-defense-check"
npm install --prefix "$YXM_DIR/openclaw" openclaw@2026.9.4
"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu doctor --bwrap /usr/bin/bwrap
看到 "available": true 后继续。这表示基础隔离可用；首次启动还会检查配置、运行文件和服务响应。隔离不可用时程序会停止，不会直接在宿主上继续运行。

这套 OpenClaw 装在本次目录内。后面会通过 --openclaw-package 使用它，无须运行 openclaw onboard 或修改个人 OpenClaw 配置。

02 / 准备资料

先放几段你看得懂的文字。

先创建一份练习资料，用它确认读取和整理过程：

cat > "$YXM_DIR/inputs/quote.txt" <<'EOF'
项目：春季客户活动（练习资料）
场地：6000 元
物料：2800 元
摄影：1200 元
备注：报价仅供内部讨论，尚未确认供应商。
EOF

可以换成自己的文件。当前只支持 UTF-8 文本，每个文件不超过 256 KiB，暂不直接读取 PDF、Word、Excel 或图片。

创建实例时会复制文件，后来修改原文件不会自动同步。要换资料，请创建另一个实例；当前还没有向已有实例增删资料的命令。

03 / 连接模型

填写自己的接口和模型名称。

模型服务需要支持工具调用和 OpenAI 兼容的 Chat Completions 接口。接口地址通常以 /v1 结尾；网页聊天账号本身不是模型接口。

云端服务须用 HTTPS。本机服务可以是 http://127.0.0.1:1234/v1，但必须能从当前 Linux / WSL 访问。运行后会询问接口地址和模型名称；HTTPS 服务还会隐藏输入 API 密钥。

read -r -p "模型接口地址（通常以 /v1 结尾）：" YXM_MODEL_URL
read -r -p "模型名称：" YXM_MODEL_ID
"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu openclaw init \
  --profile "$YXM_DIR/profiles/first-chat" \
  --model-url "$YXM_MODEL_URL" \
  --model-id "$YXM_MODEL_ID" \
  --document "quote=$YXM_DIR/inputs/quote.txt" \
  --node "$YXM_DIR/tools/node-v24.16.0-linux-x64/bin/node" \
  --openclaw-package "$YXM_DIR/openclaw/node_modules/openclaw" \
  --bwrap /usr/bin/bwrap

看到 "status": "created" 就建好了，下一步再启动聊天服务。

--profile 是这个实例的独立目录，首次创建时必须不存在。它保存资料副本、聊天和权限状态，请保留它。quote 是聊天里使用的资料名称；多份文本可重复添加 --document，每份使用不同名称。
我已经用环境变量保存模型密钥

在上面的创建命令末尾加 --api-key-env YXM_MODEL_KEY，读取已导出的 YXM_MODEL_KEY。这里传变量名，不传密钥值。无交互终端或需要密钥的本机接口也可使用这种方式。

如果需要先输入密钥，可在当前终端运行：

read -r -s -p "模型 API 密钥：" YXM_MODEL_KEY
printf '\n'
export YXM_MODEL_KEY

创建成功后可执行 unset YXM_MODEL_KEY。实例会保留自己使用的本地密钥文件。

本流程没有配置 --destinations，默认没有其他发送位置。你选择的模型仍会接收完成聊天所需的内容。

04 / 开始聊天

打开 OpenClaw，试着整理这份报价。

"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu openclaw start \
  --profile "$YXM_DIR/profiles/first-chat"

在浏览器中打开输出里的 dashboard_url。这个完整链接包含实例的访问凭证，请只供自己使用。默认在本机 127.0.0.1:18911。

在 OpenClaw 聊天里输入：

请读取 quote，列出三个费用项目，算出总费用，并说明还有什么需要确认。直接在聊天里回复我。

练习资料的三项费用合计 10,000 元，供应商尚待确认。你应看到资料读取操作及模型回答。然后可以继续说“改成三句话”或“整理成表格”。

如果模型没有读取资料、工具调用失败或结果算错，需要检查模型能力和配置。只看到一句“已完成”，不能代替实际操作记录。

日常使用

关闭后，下次还可以继续。

新开 Ubuntu 终端后，运行下面两行即可打开原来的实例：

YXM_DIR="$HOME/yuanxingmu"
"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu openclaw start \
  --profile "$YXM_DIR/profiles/first-chat"

查看状态

"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu openclaw status \
  --profile "$YXM_DIR/profiles/first-chat"

今天先不用了

"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu openclaw stop \
  --profile "$YXM_DIR/profiles/first-chat"

这会关闭服务和它运行中的命令。资料、聊天和权限状态保留，下次仍能用 start 继续。只关闭浏览器标签页不会停止服务。

结束资料使用

确定不用了，再永久收回权限。

如果这项工作不应再读取或发送资料，可以执行：

"$YXM_DIR/.venv/bin/python" -I -m yuanxingmu openclaw revoke \
  --profile "$YXM_DIR/profiles/first-chat"

也可以在已登录的 OpenClaw 聊天中输入 /yuanxingmu-revoke。

撤销是永久的，本版没有恢复权限的命令。它会拒绝后续通过元星木读取或发送资料，但不会删除已经读到的内容、撤回已完成的发送或停止本地计算。要同时关闭服务，再执行 stop。

预览版说明

遇到问题，先看程序的实际状态。

隔离检查没通过

查看 doctor 输出中的 reason，确认在 Linux / WSL 内使用系统 Python 和 bubblewrap。如果电脑限制了隔离能力，需要换受支持环境或请管理员处理。不要跳过检查继续运行。

实例目录已经存在，或者模型连接失败

已有实例用 start；新工作使用新的目录名。模型报 401、404 或无法调用工具时，核对密钥、接口地址、模型名称及工具调用支持。资料太长时，先用短文本重新建立实例。

启动失败、端口被占用或服务异常中断

查看实例目录里的 supervisor.log 和 gateway.stderr.log。端口占用时，新建实例可加 --port 18912。

如果状态是 interrupted 或 unconfirmed，表示异常退出后的清理还没有确认。保留日志与 lifecycle.json，先检查记录中的进程，不要删除权限库或改状态绕过检查。

更换版本或直接修改实例配置后不能启动

当前实例保留创建时的资料副本与校验记录。请使用指定的 OpenClaw 2026.9.4，不要直接修改生成的配置或替换运行文件。本版暂未提供原地升级与恢复撤销权限的流程。

能直接接飞书、Slack 或邮箱吗？

当前发送扩展需要开发者配置固定的 JSON 接收接口，还不是这些服务的现成连接器。这个入门流程直接在聊天里看结果，无须配置接收方。

这是一个需要实际环境验证的预览版，没有通用防护率承诺。完整参数与排错说明见仓库文档 ↗。
