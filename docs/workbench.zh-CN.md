# 用元星木整理一份资料

元星木为每项工作单独保存资料和权限。你在页面里连接模型、导入短文本，再到 OpenClaw 原来的聊天界面中看 AI 的回答。

**你选择的模型会看到聊天和使用的资料。** 云端模型会接收这些内容；元星木限制的是额外的资料读取和发送。默认不会向其他位置自动发送；新版工作支持先起草邮件，再由你核对全文并确认发送。

这是 Linux / WSL 预览版，首次安装仍需要终端。安装完成后，连接模型、导入资料、打开和关闭工作都可以在页面中完成。目前支持 OpenClaw 2026.9.4；Hermes 的终端接入实验不等于这个工作台也支持 Hermes 聊天。

## 第一次打开

先完成[安装说明的第 1 步](openclaw-quickstart.zh-CN.md#1-安装到一个独立目录)。默认安装位置是 Linux 的 `~/yuanxingmu`。然后在同一个 Ubuntu 终端运行：

```bash
"$HOME/yuanxingmu/.venv/bin/python" -I -m yuanxingmu desk
```

程序会打开本机工作台。如果浏览器没有自动打开，复制终端中完整的 `http://127.0.0.1:18910/#access=…` 链接到这台电脑的浏览器。

这个链接是你的管理入口，请只供自己使用。它和 OpenClaw 的聊天入口不同。重新启动工作台会生成新的管理链接；工作和原有权限仍然保留。

如果之前安装的是旧版，需要先更新安装目录里的仓库，再在该目录重新安装 Python 包。不要修改已建工作的配置、权限文件或运行版本来强行升级。

## 在页面里建立第一项工作

1. **起个名字。** 例如“整理活动预算”，方便下次找到。
2. **填写模型连接。** 输入模型服务给你的接口地址、模型名称和 API 密钥。需要支持 Chat Completions 和工具调用的模型接口；网页聊天账号本身不是接口。云端地址用 HTTPS，本机服务可用 `http://127.0.0.1:1234/v1` 一类地址；本机无密钥服务可以留空。
3. **导入一份短文本。** 选择 UTF-8 的 `.txt` 或 `.md` 文件，给它一个聊天时能引用的名称，例如 `quote`。
4. 点击“创建独立工作”。创建成功后，在卡片中点击“启动工作”；启动可能需要几十秒，完成后再点“进入 OpenClaw”，打开真正的聊天界面。

模型密钥会保存在这台电脑的工作目录中，供后续重新打开使用。页面不会把它放进浏览器存储或操作记录。

可以先把下面内容保存为 `quote.txt`，然后在页面选中这个文件：

```text
项目：春季客户活动（练习资料）
场地：6000 元
物料：2800 元
摄影：1200 元
备注：报价仅供内部讨论，尚未确认供应商。
```

当前最多 8 份文本，每份 256 KiB，合计 1 MiB。PDF、Word、Excel 和图片还不能直接导入。模型能否一次读完，另受它的上下文长度限制。

创建时会保存文件副本。后来修改原文件，不会改变这项工作的资料；本版要换资料时请建立新工作。

## 去 OpenClaw 聊天

点击页面提供的聊天入口，在 OpenClaw 输入：

> 请读取 quote，列出三个费用项目，算出总费用，并说明还有什么需要确认。直接在聊天里回复我。

这份练习资料合计 **10,000 元**，供应商尚待确认。你可以继续要求“改成三句话”或“整理成表格”。模型仍可能读错资料或算错；元星木控制操作权限，答案需要你核对。

聊天窗口是 OpenClaw 自带的界面。工作台负责管理这项工作，不另外模拟一套聊天或生成演示回答。

## 让 AI 起草邮件，由你确认发送

新建的工作卡片中有“查看邮件草稿”。先在“发件邮箱设置”中填写自己的邮箱连接，再让 AI 起草。打开草稿，核对收件人、主题和全文；需要改动时保存修改，再重新确认。只有点击“确认发送这封邮件”才提交邮件，AI 没有这个确认入口。

发送完成后保留实际结果。显示结果不明时，先到邮箱核对，不要重复发送。每封草稿只有一次提交机会；邮箱服务接收不等于对方收到或阅读。详见[邮件使用步骤](email.zh-CN.md)。旧工作不会自动启用邮件功能。

## 下次继续，还是彻底收回权限

| 你想做什么 | 页面操作 | 实际效果 |
| --- | --- | --- |
| 今天先不用了 | 暂时关闭 | 关闭这项工作及其运行中的命令。正常关闭后可继续原来的工作。 |
| 继续整理资料 | 启动工作 / 获取聊天入口 | 使用原来的资料、聊天和权限，再点击“进入 OpenClaw”。 |
| 查看是否还在运行 | 刷新状态 | 查看实际状态，不修改权限。 |
| 永久禁止继续读取、发送资料 | 永久收回权限 | 需要再次确认；此版本不能恢复。重新打开或换会话不会恢复权限。 |

收回权限不会删除 AI 已经读到的内容，不会撤回过去完成的发送，也不会停止本地计算。需要一起结束运行时，再点击“暂时关闭”。

**关闭浏览器标签页或退出工作台，不会关闭运行中的 AI。** 先在页面关闭需要结束的工作，再退出终端中的工作台。

页面显示异常或“尚未确认关闭”时，不代表服务已经安全退出。请保留目录和日志，确认进程情况；不要删除权限记录或修改状态绕过检查。

## 文件保存在哪里

默认在 Linux 的 `~/yuanxingmu/workbench` 下：

- `profiles/`：每项工作的资料副本、聊天、模型密钥和权限记录。
- `catalog.json`：工作名称和操作记录，不包含模型密钥和资料正文。

这些位置仅供当前系统用户访问。它不是多人共享的管理平台；不要把工作台端口代理到公网。程序只监听 `127.0.0.1`，不会提供绑定外网的选项。

页面提交失败时，再次确认实际状态。对同一次网络请求的重试会返回原操作，工作台重启后也不会自动重新执行未确认的操作。

如果电脑断电或程序异常退出，有些工作可能需要检查后才能继续。本版没有删除、重置权限或修复缺失记录的按钮。

## 安装在其他位置

终端可以指定安装位置，或显式指定已经安装的运行文件。浏览器页面不能提交这些路径或任意命令。

```bash
python -I -m yuanxingmu desk \
  --install-root /home/me/yuanxingmu \
  --data /home/me/yuanxingmu/workbench \
  --node /home/me/yuanxingmu/tools/node-v24.16.0-linux-x64/bin/node \
  --openclaw-package /home/me/yuanxingmu/openclaw/node_modules/openclaw \
  --bwrap /usr/bin/bwrap
```

工作台数据目录首次使用时应不存在；已有工作台使用原目录。不要预先创建一个空的 `workbench` 目录。运行时只能有一个工作台管理同一目录。

更详细的[命令行使用和排错](openclaw-quickstart.zh-CN.md)、[运行机制与边界](openclaw-runtime.md)仍然保留。
