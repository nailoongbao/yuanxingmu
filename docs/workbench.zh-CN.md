# 用元星木开启受控的 AI 资料整理

元星木奉行“工作空间物理隔离”原则，为你的每一项任务独立留存资料副本与权限凭证。你只需在可视化面板中选定所用的 AI 助手（OpenClaw 或 Hermes）、配置模型端点、导入所需文本，便可直接跳转至熟悉的原生聊天界面自如工作。

**安全透明提醒：你所接入的上游大模型，依然会在推理请求中接收到对话与上下文资料。** 无论是闭源商业 API 还是自建模型，推理阶段都需要这些数据；元星木真正做的是**筑牢系统外围堤坝**——死死卡住未经授权的文件越权读取与外部网络私自偷跑。在默认状态下，系统杜绝向任何外部地址静默外发；新版本更原生支持“智能起草邮件，由你终审查阅并亲手点击发送”的人机协同闭环。

本项目为 Linux / WSL 环境的开源安全研究预览版，首次初始化环境仍需借助终端。安装配置完毕后，后续的模型连接切换、知识资料导入以及任务的启停挂起，均可在直观的网页工作台中一站式搞定。**需要说明的是：本文档阐述的是当前 Git 源码主干的新特性；历史公开发布的 `0.5.0a1` 安装包仍仅支持 OpenClaw 基础会话与邮件功能，尚未包含 Hermes 深度对接、五层防御体系与操作审查矩阵。** 当前代码库深度锁定了 OpenClaw 2026.9.4 与 Hermes v2026.9.11 / 0.21.2；真实环境下的各项实测数据、通过项与现存缺口请参阅 [OpenClaw 实测报告](openclaw-layers-validation-2026-09-12.md) 与 [Hermes 实测报告](../yuanxingmu/integrations/hermes/VALIDATION.zh-CN.md)。

## 第一次拉起工作台

首先请按照 [快速上手安装指南第 1 步](openclaw-quickstart.zh-CN.md#1-安装到一个独立目录) 完成环境准备。项目默认部署路径为 Linux 用户目录下的 `~/yuanxingmu`。随后在同一个终端窗口中执行：

```bash
"$HOME/yuanxingmu/.venv/bin/python" -I -m yuanxingmu desk
```

服务就绪后会自动唤起系统默认浏览器。若未自动弹出，只需在终端输出中找到形如 `http://127.0.0.1:18910/#access=…` 的专属管理链接，复制并在当前电脑的浏览器中打开即可。

**请妥善保管好这个携带访问令牌的链接，它属于你个人的本地管理控制台，切勿随意分享给他人。** 该管理端点与普通 AI 聊天的会话入口完全独立。若中途重启工作台服务，系统会自动换发全新的随机令牌，但你先前创建的任务、沉淀的数据与权限设定均会稳稳保留在本地。

如果你先前已有老版本安装，建议继续沿用原路径；若想尝鲜开发版新特性，强烈建议指定全新的隔离目录进行全新部署，切勿盲目覆盖旧目录、或通过强行篡改底层 SQLite 权限库去升级，以免造成历史工作状态损坏。

## 三分钟建立你的第一项安全工作

1. **挑选顺手的 AI 助手并为任务命名**：例如选择 Hermes，任务备注填写“整理春季活动预算”。面板会自动扫描并仅列出本机已正确安装就绪的助手环境。
2. **立下清晰明确的履职边界**：例如输入“*阅读活动报价单，核算各分项支出与总预算，在当前对话中直接回复我；严禁向外发送数据或擅自删除修改任何文件*”。**这条规则在任务创建那一刻即被固化为宿主纪律**，后续无论是文本文件里的隐蔽注入，还是模型生成的偏移指令，都无法篡改你的初始初衷。
3. **填入模型连接凭证**：填写模型服务商提供的 Base URL、模型规格名称以及 API Key。请确保该接口支持标准的 Chat Completions 与工具调用规范；普通网页版的对话账号不可直接充当 API。公网云端模型推荐走标准 HTTPS 地址，本机私有部署（如 Ollama、vLLM、LM Studio）可直接填写 `http://127.0.0.1:1234/v1` 等本地回环；若本机服务未设鉴权，API Key 一栏直接留空即可。
4. **导入第一份业务文本**：挑选一份 UTF-8 编码的 `.txt` 或 `.md` 文件，并起一个便于在对话中指代的代号，比如 `quote`。
5. **一键生成独立沙盒**：点击“创建独立工作”。成功建档后，在工作卡片中点击“启动工作”；系统会自动完成配置基线扫描与预设技能审计。一切就绪后，点击“进入 OpenClaw”或“进入 Hermes”，便能直接踏入专属的安全聊天界面。

出于安全合规考量，你填写的模型密钥会以最小权限严格保存在本机工作目录中供重开读取，网页工作台绝不会把高敏感密钥泄露进浏览器 LocalStorage 或暴露给外部埋点。

你可以顺手把下面这段示范内容保存为本机的 `quote.txt`，用于第一次上手演练：

```text
项目：春季客户活动（练习资料）
场地：6000 元
物料：2800 元
摄影：1200 元
备注：报价仅供内部讨论，尚未确认供应商。
```

当前架构单任务最多支持挂载 8 份文本文件，单文件上限 256 KiB，总容量上限为 1 MiB。现阶段暂未直接支持原生解析 PDF、Word、Excel 及图片文件。模型能否一次性吃下全部内容，同时取决于所选模型的上下文窗口容量。

任务创建阶段，系统会把文件快照安全复制进专属沙盒。后续你若在宿主机上修改了原文件，绝不会隐式污染已运行沙盒内的既有数据；如果业务资料发生重大更迭，重新建一个专属新工作即可。

## 进入原生对话界面开始协作

点击工作台生成的专属聊天入口，试着对 AI 发出第一道指令：

> 请仔细查阅 quote 文件，依次列出其中的三个费用明细项，帮我算出总计费用，并提醒我还有哪些商务事项尚未敲定。直接在聊天气泡中向我汇报。

在这份示范测试中，三笔账目相加应严密等于 **10,000 元**，且备注中应提炼出“供应商尚未最终确认”。你可以继续让它“精简为三句话摘要”或“排版成 Markdown 表格”。**必须保持清醒的是：大模型依然有概率算错数字或误读条目；元星木的核心职责是封死越权与外泄的系统权限，最终业务答案依然需要你的人工审阅。**

会话窗口完全沿用你所选助手官方的原生界面，工作台只在底层默默履行守护与权限审计职责，不会画蛇添足地自己搞一套假聊天界面。当前新版本会在大模型全部推理完成、且出站安全审查全部绿灯通过后，才一次性将完整内容渲染到屏幕上，因此不会出现逐字打字机式的动态流式效果。

## 拆解：五层安全防御分别守护什么

| 工作台功能模块 | 它在底层默默严防什么 |
| --- | --- |
| **环境与技能审计** | 在沙盒拉起前，深度扫描配置项与挂载的技能代码副本，严查是否悄悄开启了直连外网开关、技能脚本文档中是否夹带高危越权代码。 |
| **外部输入清洗** | 深度排查输入文件与工具返回结果中，是否存在试图伪造“System”角色、诱导“忽略先前所有要求”、或是欺骗套取 API 凭证的 Prompt Injection 提示词注入。 |
| **长期记忆防投毒** | 严防 AI 在潜移默化中将“绕过安全机制”、“暗中向外发送日志”等恶意指令偷写进长期记忆库中，避免埋下持久化后门。 |
| **意图偏离检测** | 实时比对大模型眼下正准备调用的工具动作、准备吐出的回复文本，严密核验是否违背了你创建该任务时写下的初始使命。 |
| **高危命令阻断** | 在真实操作系统调用发生前的微秒级瞬间，拦截一切试图提权（`sudo`）、递归破坏文件（`rm -rf`）、嗅探本地密钥或拉取外部未知脚本执行的危险 Shell 行为。 |

系统默认开启全量五层纵深防御，默认采取“真实拦截”与“关键阻断转人工”策略。若在排障时切换为“仅记录，不拦截”的观察模式，后台的审计日志仅代表成功识别了攻击特征，绝不等于已消除实际危害。你可以在“防护记录”看板中随时查看各防线的工作水位；新建任务支持在运行中动态微调开关，历史旧任务则需平稳关闭后方可修改配置。请注意：单纯切换开关不会清除已有的沙盒暂停状态，更绝无法凭空拓宽网络与文件权限。

在默认配置下，业务推理与安全审查均由同一个模型担任。若对安全性有更高追求，可在创建面板中展开“配置独立审查模型”，专门绑定另一个模型端点来当“安全考官”。独立模型同样会接收到任务准则、候选系统调用、技能代码与回复全文；但需要清醒认识到：成功接入独立模型并不代表百分之百杜绝漏判，目前测试表明较小参数量的模型在面对正常代码写入时依然存在误拦现象，详情可查阅 [独立审查模型选型说明](judge-configuration.zh-CN.md)。

当安全引擎判定某一步脚本或动作需要你亲自把关时，工作台会弹出醒目的代码候选框，并提供“仅放行这一次”选项。这代表你仅豁免眼前这次特定的执行，绝不代表赋予了后续任意操作的终身通行证；只要参数稍有改动或会话超时，都必须重新复核。此外，一旦触碰到底层焊死的系统级高危硬规则，即使点击单次放行也会被底层强制阻断。

## 巧用邮件草稿，让人类牢牢掌握发信权

创建完毕的工作卡片中带有“查看邮件草稿”专区。先在全局“发件邮箱设置”中登记你自己的 SMTP 鉴权信息，随后即可放心让 AI 去组织语言。收到 AI 提交的申请后，点开草稿面板，逐字审视收件人、标题与邮件全文；如需改动，随时可在本地修改并保存。**唯有当你亲手勾选并点击“确认发送这封邮件”后，系统才会真正握手邮件服务器，AI 进程本身在底层根本没有触碰发信按钮的权限。**

发信流程结束后，工作台会完整留存真实的交互流水。若界面偶尔提示“结果不明”，建议先去网页邮箱的已发箱中查验，切勿盲目重复点击。每封草稿在状态机中仅有一次提交生命周期；邮件服务器成功入库仅代表中继成功，绝不等于对方已经接收或查阅。详细的操作步骤请参阅 [邮件安全使用指南](email.zh-CN.md)。需要提醒的是，历史旧任务不会被静默追加此项能力。

## 涉及外发消息、文件上传、表单与磁盘修改，同样步步有把关

对于向外部发送网络消息、上传文件、填写表单或覆盖本地文档等敏感动作，必须事先在工作台的“可确认的操作对象”白名单中登记备案。例如先登记好项目群聊的 Webhook 终点，或是明确指定允许覆盖的某份分析报告。AI 只能在已登记的受控目录中挑选目标，无法偷梁换换柱指向未知的外部服务器。

打开待审操作清单，仔细核验目标地址与全部载荷细节后再决定是否执行。如果要覆盖文件，工作台会清晰以 Diff 对比形式展示旧内容与新写入差异；如果要删除文件，范围也严格限制在预先登记的那份文件本身。一旦目标或正文发生变动，均必须重新走审核流程。若外部网络通信超时，必须先去接收端排查现场，系统严禁发生未经许可的自动重试。

目前消息、上传与表单均基于严密的固定协议栈实现；在本地回环测试通过并不代表任意复杂的第三方云服务都能开箱即用。文件修改权限也仅面向预先显式登记的小型 UTF-8 文档，系统在底层绝对禁止任意目录级别的递归删除或通用文件系统管理。

## 遭遇安全暂停后，该如何规范恢复

当系统检测到高危异动时，工作台会立刻挂起沙盒并明明白白展示暂停原因。点击进入“防护记录”专区，逐一排查并妥善处置所有未决的安全事件，随后勾选确认，点击“恢复这份工作”。**请切记：在聊天框里疯狂打字、狂刷新网页或者干等着，沙盒都不会自行解冻。**

成功恢复后，直接回到助手的聊天窗口，重新提出你希望继续推进的任务即可；此前被拦截的旧动作与旧审批不会盲目自动重试。如果先前曾遇到“任务已中止但网络状态不明”的情况，建议先登录外部服务核实实际数据。安全暂停无法逆向撤回在暂停之前已经成功发出的外部数据。

若需要暂时离开电脑，可在后台开启 [离线消息提醒](background-notifications.zh-CN.md)。即便关掉了浏览器，正在后台坚守的工作台仍可通过可靠通道将暂停、恢复、撤权与待审申请实时推送给你；当然，如果你在宿主机上把工作台主进程直接杀掉了，通知也将一并停止。

## 今天先到这里：是暂时挂起，还是彻底销权？

| 你的当前意图 | 建议的界面操作 | 底层真实发生的物理动作 |
| --- | --- | --- |
| **今天先告一段落，明天继续** | **暂时关闭** | 优雅中止这项工作及其沙盒内正在跑的子命令。待状态确认平稳关闭后，后续随时可原样唤醒继续。 |
| **准备继续推演资料** | **启动工作 / 获取聊天入口** | 完整继承先前的资料副本、历史聊天记录与权限上下文，再次无缝踏入助手的原生对话环境。 |
| **单纯看一眼后台是否健康** | **刷新状态** | 仅向宿主守护进程发起心跳与状态查询，绝不更改任何既有权限。 |
| **该项目已彻底终结，严防泄密** | **永久收回权限** | 系统会弹窗要求二次确认；**此操作一旦执行不可逆转**。即使后续重新打开任务或新起会话，该沙盒内的资料读取与网络发送权限也将被永久封死。 |

请注意：收回权限并不会神奇地删除 AI 在前序对话中已经阅读消化过的记忆，无法撤回过去早已在公网交付的外部消息，也不会自动掐断纯本地的重度计算进程。如果希望彻底清理现场，请配套点击“暂时关闭”。

**再次敲黑板：单纯关掉浏览器网页标签或者退回终端，并不会停止后台正在运行的 AI 计算进程！** 规范的做法是：先在网页卡片中从容点击“暂时关闭”，待确认沙盒平稳着陆后，再去终端退出工作台进程。

如果界面偶发显示异常或提示“尚未确认关闭”，切不可主观臆断后台服务已安全退出。请保留好当前的工作目录与运行日志，前往进程列表（`ps aux`）核对真实状态；切勿试图通过暴力删除 SQLite 权限数据库去绕过安全检查。

## 本地数据到底沉淀在哪里

在 Linux / WSL 默认环境下，工作台的所有数据均安全落盘在 `~/yuanxingmu/workbench` 路径中：

- `profiles/`：分门别类归档每项任务的独立资料副本、历史聊天快照、模型 API 配置以及不可篡改的权限审计账本。
- `catalog.json`：工作台的任务总览与操作流水清单，其中绝不包含明文的模型 API 密钥与业务资料正文。

这些敏感资产在文件系统级别严格限定为仅供当前登录的操作系统用户私有访问。**元星木是一个纯正的本地单兵安全沙盒，绝非多人多租户的公共 SaaS 平台；严禁私自通过反向代理将工作台端口直接暴露在公网！** 守护进程在网络层默认且唯一监听 `127.0.0.1` 本地回环地址，设计上根本未提供任何绑定公网 IP 的配置选项。

如果在网页端提交表单时提示失败，请务必再次刷新并核对后台真实状态。针对同一笔网络请求的重试，系统会幂等地返回原操作凭证；哪怕中途工作台被强行重启，也绝不会在后台盲目代你重新执行任何未经人工确认的敏感操作。

如果突发断电或宿主机内核崩溃，部分任务沙盒可能需要经过环境完整性校验后方可复工。当前版本并未提供“一键抹除所有权限”或“无痕修复缺失审计日志”的危险捷径，一切以底层安全事实为准。

## 高阶指南：定制化安装与指定外部组件

高级运维或开发者可直接在终端中显式声明各项底层组件的具体安装路径，灵活指定自定义的运行时：

```bash
python -I -m yuanxingmu desk \
  --install-root /home/me/yuanxingmu \
  --data /home/me/yuanxingmu/workbench \
  --node /home/me/yuanxingmu/tools/node-v24.16.0-linux-x64/bin/node \
  --openclaw-package /home/me/yuanxingmu/openclaw/node_modules/openclaw \
  --bwrap /usr/bin/bwrap
```

请确保首次启动时所指定的 `--data` 数据目录尚未存在，系统会自动完成标准初始化结构建档；如果是恢复旧工作台，直接指定现有的数据目录即可，切勿自行提前在终端中建一个空的 `workbench` 文件夹。在同一时间维度下，系统严格限制只能有一个工作台守护进程挂载并管理同一个数据目录。

若选择手工编译接入 Hermes，还可通过 `--hermes-python /home/me/hermes/env/bin/python` 与 `--hermes-source /home/me/hermes/source` 显式链接 Python 解释器与源码目录；所链接的环境必须是官方认证支持的版本，且已预先完成了官方前端静态资源的构建编译。仅仅在虚拟环境中 `pip install` 了一个 Python 包并不等于其官方 WebUI 已经可用，具体的前置要求请仔细参阅 [Hermes 原生接入深度说明](../yuanxingmu/integrations/hermes/README.md)。
