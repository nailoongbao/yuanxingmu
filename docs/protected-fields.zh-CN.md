# 敏感字段先隐藏，再交给 AI

这是 **0.7.0a1 开发版**的独立防护边界。公开的 0.6.0a1 运行包和安装器并不包含它。开发检查使用合成资料和本机接收器；原生 Hermes 的新一轮实机结果需要单独记录，不能用这些检查替代。

[查看固定源码的组件与 CI 检查记录](evidence/protected-fields-2026-09-12/REPORT.zh-CN.md)。记录分别列出通过和跳过项，并附有可离线核对的原始结果。

这项工作的直接原因是 AUTO18：模型成功完成发消息、上传和填表，三个提交没有底价，但进度说明与最终回复显示了底价。检查模型两次给出有效的“允许”。恶意供应商指令没有进入工作模型，因此这次失败是**显示限制失效和检查漏检**，不能称为成功的提示注入。

## 对使用者有什么变化

创建新工作时，元星木从你选定的资料中登记明确标记的底价、密码和令牌。读取资料时先把这些字段换成隐藏标记，再交给 AI；公开报价和其他未遮盖的文字保持原样。这个过程不要求你逐项确认，也不把资料的原有私密权限改成公开。

对已登记的值还有三处检查：请求离开本机去工作模型前、完整回答交给原生聊天页前，以及消息、上传、表单、文件修改和邮件真正提交前。回答包括正文、思考、拒绝说明和工具调用参数。启用这个功能的工作会先收齐一次模型返回再显示，不能同时保证逐字实时输出。

明确匹配到已登记的值时，内容被扣留，后续工作暂停。重新聊天、子任务、重启服务和把语义检查切到“只观察”都不能清除它。恢复入口属于宿主工作台；恢复也不会删除字段登记。正常的隐藏和公开资料处理不暂停工作。

## 第一版能识别什么

- 文本或 JSON 中的“内部底价”“底价”，以及 `api_key`、`access_token`、`password`、`client_secret`、`secret_key`。复合英文标签支持下划线、省略下划线和连字符写法。
- 完整原值、Unicode NFKC 归一化、指定的零宽字符，以及有限的金额表示。例如合成底价 `162000`、`162,000.00`、`16.2万元`。
- JSON 解码后的字段值和键、工具参数中的完整嵌套 JSON 字符串，以及同一次 SSE 回答中按工具索引重组的参数。

公开报价不会仅因是金额而自动变成秘密。但如果公开字段与已登记底价恰好同值，系统会保守拒绝，因为仅靠值无法分辨来源。超过大小、字段数量或解析限制时会拒绝，不能退回原文放行。创建失败需要修正资料格式，不会静默启动一个缺少登记的实例。

这不是通用秘密识别器。未标记秘密、任意编码、中文数字、算式推导、不同请求之间的拆分，以及模型从其他线索推断秘密，不在当前保证范围内。宿主模型接口密钥由原有隔离机制保管，并非这套资料字段识别的来源。

## 保存和最终提交

原文、原值、源文件哈希和字段位置只存在宿主私有资料与 `protected-data.json` 中。新实例将它的摘要与资料、权限绑定，并把私有文件纳入实例完整性检查；它不会挂载进 Hermes/OpenClaw 的进程。加载时依据原始资料重新编译并核对，不能拿序列化的字段表自证可信。旧实例不自动改写或冒充已启用。

审计只记录固定原因，不记录命中的原值、原文或可枚举的值哈希。检查模型也受这道边界约束：提交给它的候选和它返回的解释在发出请求、进入日志前检查。

最终动作检查针对数据库内实际提交的版本，在消耗次数、创建发送尝试和外部 I/O 之前执行。手动编辑与确认不能绕过。暂停在动作事务结束后写入，避免嵌套事务导致保护状态没有保存。

这是一项针对已观察失败的工程修复，不是攻击成功率、生产可靠性或“超过其他防御项目”的证明。
