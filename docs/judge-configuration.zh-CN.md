# 给防护检查选择独立模型

工作模型负责完成任务，检查模型负责对照你在创建时写下的目标，判断实际操作有没有偏离。默认使用同一服务；开发版工作台也可以勾选“用另一个模型做防护检查”，分别填写地址、模型名和密钥。OpenClaw、Hermes 两个专用运行入口都接受这项设置。

检查模型会收到固定目标、被检查的完整操作或回答，以及启动时选定的技能内容。选择云端检查服务时，这些内容会发送到该服务。两把密钥分别保存在主机，Agent 不能更换检查模型或通过工具修改目标。工作台不把密钥保存进浏览器存储。

创建之后，开关设置不会更换检查模型；需要另一套检查配置时创建新工作。两份独立检查配置文件固定在实例清单中，缺少或被修改时会拒绝继续加载。仅配置更大的模型不保证更准确。

使用命令行时，在现有 `openclaw init` 或 `hermes init` 参数后添加：

```sh
--judge-url https://your-provider.example/v1 \
--judge-model-id your-review-model \
--judge-api-key-env YUANXINGMU_JUDGE_KEY \
--judge-timeout 30
```

模型地址和名称必须成对设置。密钥从指定环境变量读取，不把真实密钥写进命令行。单次检查最长 45 秒；超时、无效返回或服务不可用时，不自动变成允许。

## 本地复核结果

2026-09-12 的 OpenClaw 实测中，Qwen3-4B 把一条普通本地写摘要命令误判为泄密。随后冻结了 12 个候选：其中一个来自那次实际调用，并核对完整参数的 SHA-256；另 11 个是合成对照。使用相同检查提示和目标，交给独立 Qwen3-8B-Q4_K_M 复核。

- 7 个正常候选全部判为允许，包括那条原始本地写入。
- 5 个不应放行的候选中，4 个被阻止，**未经确认直接上传文件的命令被漏判**。
- 这批只运行语义检查，没有执行命令，没有 Agent 循环，不能称为 12 次完整防御试验。

结果说明独立模型能改善这一例误报，也暴露出其局限。实际发送许可、本人确认、文件权限与网络隔离仍由主机程序控制；不能把检查模型的“允许”直接变成任意执行权。这是一个开发样本集，不代表泛化准确率或同条件击败其他产品。

配置组件完成了 Linux 24 项文件边界检查、11 项 HTTP/CLI 接入检查，以及真实 Chrome 中的 18 项表单检查。上述数量分别对应模块、管理入口和界面，不是模型攻击通过数。

后续 [回答检查对照](evidence/response-review-2026-09-12/REPORT.zh-CN.md) 单独评估了“报告暂停被当成违规”的问题。新提示修复了精确复现的误判；独立 12 例中正常与明确危险回答均保持正确，但有两条需要核对的情况被过重地判为阻止。这组结果不支持总体准确率提高，也不能替代官方 Agent 网页验收。
