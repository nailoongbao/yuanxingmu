# 宿主审定 Wheel 制品清单与快照机制

`yuanxingmu.wheel_store` 将宿主事先选定的二进制 wheel 制品复制为可复验的私有快照。它核对实际发布的字节是否与宿主固定清单一致，不安装包、不解析依赖、不接入 Agent 工具调用，也不批准任何代码运行。

## 核心设计与安全边界

1. **可信清单先于扫描存在**：
   - 宿主通过 `ExpectedWheelManifest` 预先固定选定文件的名称、确切字节大小与 SHA-256 哈希，使用 tuple 保存 `ExpectedWheel` 条目。清单和 `WheelLimits` 严格检查类型、重复名称和资源额度，bool/float 不能代替整数字节数。
   - `publish_wheel_store(source_dir, expected_manifest, store_root)` 不会根据任意目录自动批准新的哈希。检查到源目录多项、缺项、链接、特殊文件或读取期间的身份、大小、时间变化时拒绝发布。
   - 文件名检查接受常见版本、本地版本、build tag 和平台 tag 字符；它不证明文件符合完整 wheel 规范，亦不验证 ZIP 内容、METADATA、依赖闭包或 Python/平台兼容性。
2. **描述符级校验与原子复制绑定**：
   - 仅支持 Linux 原生文件系统语义，包括目录描述符、nofollow 和原子不覆盖重命名；平台不支持时明确失败，没有 Windows 等价回退。WSL 验收使用 Linux 文件系统中的临时目录。
   - 路径必须是绝对路径，逐级拒绝链接；源和 store 不能互相包含。store 根目录可以新建，父目录须预先存在并满足归属和权限要求；已有 store 不能靠自动 chmod 修复。store 根目录为 `0700`，单个快照目录为 `0500`，文件为 `0400`。
   - 在私有 staging 中有限地读取、复制并计算哈希，核对 fd、路径和目录在操作前后是否一致。文件与清单完整写入并同步后，使用不覆盖已有目标的原子发布；竞争或冲突时复验既有快照，不能覆盖它。失败只清理本次 staging，不删除已有 digest。
   - `verify_wheel_store(store_path, expected_manifest, expected_manifest_digest=None)` 总会比较完整规范清单和全部制品，省略第三个参数不代表跳过清单绑定。提供的 digest 及目录名也必须与宿主预期一致。清单和制品均检查类型、单链接、归属、权限、大小、哈希及读取期间变化；FIFO 不会等待写入者，增长文件不会无限读到 EOF。
3. **安全边界声明**：
   - 本接口不冻结源目录。元数据前后检查只检测可观察的变化，不证明整个源目录在操作期间从未改变；实际发布的制品仍按宿主固定的大小与哈希完整复验。
   - 仍信任宿主及其私有 store。chmod 不能隔离拥有相同宿主身份的进程；复验返回后，调用者仍须保护该快照的生命周期，并在启动前复验、通过只读挂载供隔离 Worker 使用。不能另给 Worker 可写路径或别名，不能把一次复验当成永久防替换保证。
   - 真实任务挂载、安装目标、配置来源、依赖解析及离线安装均是后续工作。`--no-index` 只停用索引，不能替代直接 URL 限制与网络隔离；哈希匹配也不能证明代码没有恶意。
   - [包管理器显式改源复核](package-source-review.zh-CN.md) 是另一项有限命令规则，并不自动调用本模块。

本模块是源码中的宿主开发接口，没有工作台安装入口。固定 runtime `0.7.0a2` / installer `0.4.0a2` 下载文件尚未包含。
