# 回答显示前检查与暂停恢复

更新日期：2026-09-12。

元星木新增了两件事：模型的回答先收齐、检查，再送到聊天界面；发现需要阻止的问题后，由主机暂停这份工作及它分出的任务，等待本人处理。已经开始的操作仍要核对结果，不能因为页面显示“暂停”就认为它们已经撤回。

代码和组件测试已有记录。Hermes 的 native13/GLM14 已补齐同源码五层固定案例、真实工作台恢复和五段解说视频；较新的 AUTO15 自动消息实际送达后，正常回答被误拦，连续工作验收失败。各轮范围见下文，不能合并成所有框架、全部来源或最新代码都通过端到端验收。

## 普通用户会看到什么

1. 回答不再逐字实时出现。主机先等这一段模型响应结束，再检查其中的文字。
2. 检查通过后，聊天页收到原回答；强制模式下未通过时，只显示带“元星木防护提醒”的说明。
3. 工作暂停后，工作台显示原因。后续工具调用无法取得新的执行许可，尚未使用的审批和待确认操作会作废。
4. 处理可疑资料后，在“防护记录”里核对全部未处理原因，勾选确认，再点击“恢复这份工作”。若核对期间出现新告警，旧页面不能恢复，需要重新读取记录。
5. 恢复不自动重试旧操作，也不会恢复已作废的审批。需要回到聊天页重新发起；收到不确定的提交结果时，应先查询状态。

“恢复工作”和“允许某次代码操作”是两次不同的决定。解除暂停后，一段仍需要审批的代码依然要单独核对。

## 回答检查覆盖到哪里

当前实现接在元星木专用运行入口的主机模型网络桥上，支持 OpenAI 兼容的 `/v1/chat/completions`：一个候选回答，JSON 或 SSE 格式。SSE 是模型分段发送的格式；主机仍会把整次响应收齐，才向框架释放字节。

| 内容 | 当前处理 |
|---|---|
| 回答正文 `content` | 收齐后检查，分段文字按顺序拼接。 |
| 拒绝文字 `refusal` | 与正文一起检查，保留字段区别。 |
| 思考文字 `reasoning`、`reasoning_content` | 收齐后检查，包括框架可能显示的思考内容；不承诺模型必须提供这类字段。 |
| 附带的工具调用 | 若同次回答被拒绝，整次响应都会替换，原文和附带调用都不会放出。工具名、参数本身仍由行动前的工具防御负责，不把它们算成已通过正文检查。 |
| 工具卡、工具执行结果、终端程序输出 | 不在这项“回答正文检查”的统一覆盖承诺里；需要各自的工具、输入与执行边界。 |
| 图片、音频、视频、其他模型接口、多候选回答 | 没有完整支持承诺；强制模式下未支持的响应格式会停止展示，不取一段可解析内容冒充完整检查。 |
| 已经显示的文字、旧聊天记录 | 无法事后保证用户从未看见。回答缓冲不负责清除旧记录。 |

框架只是注册了元星木 SDK 工具，不代表模型请求也经过这条主机网络桥。LangChain/LangGraph、OpenAI Agents、PydanticAI、Google ADK、CrewAI、Agno 的工具适配应按[框架支持范围](framework-support.zh-CN.md)理解，不能据此宣布它们的所有回答都已受保护。

响应体默认最多 2 MiB。交给语义检查的内容还受策略中的 `max_candidate_bytes` 限制，默认 256 KiB；超限时强制模式会停止，不截取开头后放过剩余部分。流式响应必须完整结束，重复 JSON 字段、未知内容形式和不完整响应不能当成有效答案。传输有时限，检查服务也有独立时限；检查超时后晚到的“允许”不会重新释放原回答。

这些机制决定**检查发生在哪里、失败后是否继续**，不能保证语义判断永远正确。模型仍可能误判正常回答，或漏掉隐蔽的问题；需要保留正常任务对照和真实失败记录。

相关实现：[model_output.py](../yuanxingmu/model_output.py)、[gateway_network.py](../yuanxingmu/gateway_network.py)、[Guards.check_response](../yuanxingmu/guards.py)。

## 为什么不能只在写聊天记录时替换

官方框架的某些插件接口在文字显示以后才触发。Hermes 固定版本 `939e45c91d751fadd94dcd1b873ac3cb44846213` 的 [stream_delivery.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/agent/stream_delivery.py#L313) 先把文字交给显示回调，再发出异步流式通知；最终回答改写位于 [turn_finalizer.py](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/agent/turn_finalizer.py#L509)。官方 [网页终端桥](https://github.com/NousResearch/hermes-agent/blob/939e45c91d751fadd94dcd1b873ac3cb44846213/hermes_cli/web_server_chat.py#L71) 会直接转发终端输出。

安装的 OpenClaw `2026.9.4` 同样有独立的实时聊天发送路径：`dist/server-chat-BP_fmUto.mjs` 的 `broadcastChatDelta` 与 `emitChatDelta`。其 `before_message_write` 负责聊天记录写入；只替换记录不能证明实时文字从未显示。元星木因此在模型响应到达这些界面路径之前进行缓冲，而不是用修改历史记录来证明显示前拦截。

## 暂停怎么执行

主机在同一个权限数据库事务里保存暂停状态、推进状态编号、登记告警，并作废整项工作及子任务尚未使用的审批。子任务触发告警时，父任务和兄弟任务同样暂停，不能换一条连接继续取许可。

| 已有记录 | 暂停后的处理 |
|---|---|
| 待审核或已批准但未消费的工具许可 | 标记失效，不能再使用。 |
| 待确认的邮件草稿 | 取消原草稿；恢复不使它重新变成可发送。 |
| 待确认的消息、上传、表单、覆盖或删除文件 | 取消原操作；恢复后需重新提出并核对。 |
| 已消费的工具许可 | 保留消费记录，不能再次取得同一个许可；不宣称工具已经停止或回滚。 |
| 已进入发送或执行阶段的操作 | 保留原尝试，继续核对实际结果；暂停不撤回已经发生的效果。 |

相同的未处理判定在本次暂停周期内会去重。新候选、新理由或新证据产生新告警，状态编号随之变化；旧页面拿着旧编号不能解除新的暂停。本人恢复后，同一可疑内容再次出现仍可再次暂停。

恢复只通过主机审批入口进行，不是模型可调用的工具。必须匹配当前状态编号及最新告警，并由根任务对应的本人界面确认。工作台若拿到不完整或相互矛盾的未处理记录，不会提供恢复按钮。数据库里的恢复记录包含操作者入口信息；该字段本身不是身份凭证，身份验证由主机入口负责。

重启、换连接、继续聊天、等待一段时间或通知发送成功，都不会自动解除暂停。永久撤销优先于暂停；恢复也不能把已撤销的任务重新授权。

相关实现：[quarantine.py](../yuanxingmu/quarantine.py)、[authority.py](../yuanxingmu/authority.py)、[broker.py](../yuanxingmu/broker.py)。

## 存储失败时

暂停和审计必须成功写入后才能报告相应结果。若主机无法记录防护结果或暂停状态，会锁住故障状态，拒绝后续操作；工作台显示存储问题，不能直接点击恢复来绕过。

受保护服务在开放工作入口前保存并同步“运行尚未确认结束”的标记。异常结束或存储故障后保留标记；下次启动先暂停已有未撤销的根任务，再允许查看和处理。如果数据库仍无法完成恢复检查，服务不能开放工作入口。这个处理不回收故障前已经交给执行器的许可，也不抹掉结果不明的发送尝试。

## 暂停、停止和撤销不是同一操作

| 状态 | 含义 | 能做什么 |
|---|---|---|
| 安全暂停 | 主机拒绝新的操作许可，框架进程可能还在。 | 查看原因，处理资料，由本人精确恢复。 |
| 实例停止（`stopped`） | 运行进程已确认停止。 | 修改设置后再启动重新检查；旧实例必须先到这个状态才能修改。 |
| 永久撤销 | 这项任务及被撤销的子任务失去权限。 | 查看记录；“恢复工作”不能解除撤销。 |

工作台和 `yuanxingmu defense` 支持查看五层开关及强制/观察模式。带 `per_layer_settings_v1` 的新实例还能分别设置每层的处理方式，以及基础配置检查和技能语义检查开关；带 `skill_rules_v1` 的实例另有技能规则开关。关闭内容检查不解除技能快照和安全读取要求。[使用说明](layer-settings.zh-CN.md)解释默认方式与单独设置的优先级。带 `live_settings_v1` 的实例支持运行中修改：请求经主机专用 `review.sock` 处理，模型使用的工作接口不能修改设置。旧实例没有这个入口，必须先确认停止；**安全暂停不等于已经停止**。

`yuanxingmu defense get/set/reset` 分别查看、修改及恢复五层与扫描全开、默认强制拦截，并清除各层单独设置。新实例另有 `restore` 恢复固定保存的创建时设置，网页先列变化、本人保存才执行；旧实例没有快照时明确拒绝。工作台管理的工作只能在工作台保存；CLI `set/reset/restore` 在任何写入前拒绝，`get` 仍可用，防止实例与工作台的配置摘要不同步。独立实例可使用完整 CLI。网页的“恢复全部开启”先填好表单，点击“保存防护设置”后才生效。这种重置不是恢复实例创建时的设置，也不是撤销上一次修改。它不会重写固定工作目标、扩大资料权限、改变任务身份、解除暂停或永久撤权。主机在同一把操作锁内更新配置及清单，后续检查使用新设置；未使用的许可和待确认草稿作废。已经开始的操作不受这次改动追溯影响。

带 `settings_history_v1` 的新实例每次工作台保存都比较读时策略摘要，并在 Broker 锁内重新比较，旧页面不能覆盖另一位操作者刚修改的设置。恢复还比较创建基线摘要和完整设置。审计统一记录允许字段的前后值、实际入口和操作类型，不记录工作目标、资料正文或凭证；工作台再按字段白名单显示。无新协议的旧运行实例保持旧能力，不伪称具备新版本核对与审计。

多份配置文件并非一个文件系统事务：如果只写成功一部分，主机会进入故障状态并保留异常结束标记，不能沿用混合配置继续运行。保存后原基础扫描报告会标为旧设置（`current_policy=false`），安装与技能检查在下一次启动重做，不把旧报告当成新设置已通过。[配置实现](../yuanxingmu/protection.py)

运行中修改的管理 HTTP、主机 Unix socket、策略更新和文件写入已有 13/13 组件测试；测试中的框架进程和运行状态是受控测试对象，尚待 OpenClaw/Hermes 官方运行入口验收。[审计与恢复记录](evidence/settings-history-2026-09-12/REPORT.zh-CN.md)区分这次实现与较早的 7/7 检查点。

仅观察模式会记录“原本会阻止/需确认”，但仍放行，不算拦截成功。关闭回答所属的语义层时，该层不检查回答，也不声称保护已生效。网络传输的大小限制等基础约束仍可能拒绝请求，不能把这种失败写成语义识别成功。

## 桌面提醒的范围

工作台会显示暂停卡片，并在页签标题中显示暂停数量。点击“开启本机桌面提醒”、得到浏览器授权后，新暂停可触发本机通知。通知只提示回到工作台处理，不含资料正文。

**本机桌面提醒要求工作台页面保持开启。** 页面关闭、浏览器休眠、系统通知设置或浏览器限制都可能影响这种提醒。

另有独立的[后台提醒](background-notifications.zh-CN.md)：主机读取工作事件并写入持久发送队列，浏览器可关闭，但 Workbench 进程必须运行。支持固定的通用 JSON 接收地址，状态包括暂停、恢复、撤权和等待本人确认；重启补投，失败与容量可见，不附带工作名称、资料或指令。默认关闭，目前通过本机 HTTP 接收端验证，尚未验收第三方聊天、企业 IM 或邮件提供商，不能宣传成这些提供商的直接支持。

当前通知队列测试为 **28/28**，包含系统时间回拨、重开与旧格式迁移。升级时先停止旧工作台，再用原目录启动新版；迁移后的队列不能由旧代码同时使用。提醒失败或格式升级都不会重新授予工作权限。

[界面实现](../yuanxingmu/dashboard/web/protection.js)会按状态编号避免重复提醒；提醒失败不解除暂停。

当前状态提示检查区分了请求发生前后：暂停、永久撤权、存储故障或无法确认权限若在发送前发现，提示“本次请求未发送给模型”，并断言上游模型及裁判请求均为零。请求发出后才发生撤权或审计保存失败，则只说明“本次返回的内容已暂不展示”，不声称请求从未发出。撤权提示明确恢复暂停不能重新授权；内部错误和未知原因不会原样显示，也不会把未经检查的回答说成“未通过检查”。

Hermes 本地 `native07/08` 已记录一批真实候选命中，也记录了正常操作误报；那批运行早于本次暂停和回答缓冲集成。[`native12` 核心复验](evidence/hermes-native12-2026-09-12/REPORT.zh-CN.md)已完成官方 `write_file` 提出操作、工作台一次批准、精确 50 字节落盘；正常 `true` 通过、`sudo true` 被阻止，暂停后真正新聊天没有新增模型和工具调用。它没有覆盖后来加入的技能用途关联检查及全部设置，也不是新版五层全通过。

OpenClaw 的 [`native10` 记录](evidence/openclaw-native10-2026-09-12/REPORT.zh-CN.md)包含正常消息、表单、覆盖、删除的真实本人确认及执行，也保留正常上传被回答检查误拦。恢复后，模型在三个后续正常操作中复制了旧防护提醒；后台实际判定为允许，操作也完成。聊天文字与主机状态因此可能不一致，不能仅凭一句“已拦截”判断防御是否发生。官方 `/yuanxingmu` 可直接读取主机的当前暂停和五层状态，配置修改仍在工作台进行。
