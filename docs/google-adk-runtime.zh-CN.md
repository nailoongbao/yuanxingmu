# 在防护中运行 Google ADK 任务

`yuanxingmu sdk-run --framework google_adk` 使用 Google ADK 的真实 `Runner` 和两个固定助手运行任务：第一个助手读取资料，再把操作交给第二个助手。消息、文本上传和表单提交都由元星木检查并执行；换助手不会增加权限或重置额度。

这是 main 源码的开发入口，尚未进入 runtime `0.7.0a2` 或 installer `0.4.0a2` 下载包。它沿用已有 Hermes/OpenClaw 工作实例的任务、资料限制、保护字段与自动范围。它提供固定的双助手流程，接管任意已有 ADK 应用仍需另行适配。

## 安装与运行

先准备已启用分层防护、保护字段及回答缓冲的工作实例，并停止其原生服务。使用 Linux/WSL 系统 Python，在工作实例目录之外建立 SDK 环境：

```bash
/usr/bin/python3 -m venv ~/yuanxingmu-google-adk
~/yuanxingmu-google-adk/bin/python -m pip install -r docs/google-adk-runtime-requirements.txt

yuanxingmu sdk-run \
  --framework google_adk \
  --profile /absolute/path/to/profile \
  --sdk-python /absolute/path/to/google-adk-venv/bin/python \
  --session customer-summary \
  --prompt-file /absolute/path/to/task.txt \
  --max-steps 12 \
  --max-tokens 2048 \
  --timeout 600
```

固定依赖为 `google-adk 2.9.0`、`google-genai 2.23.0` 和 `pydantic 2.13.5`。解释器须来自 `/usr` 下的系统 Python；宿主读取依赖元数据，SDK 在隔离进程内导入。模型沿用原工作实例的配置，通过宿主的 Chat Completions 通道连接，真实密钥留在宿主。

启动前会核对原工作的工具权限。原来的 `allowed_tools` 如果只允许 Hermes/OpenClaw 原生工具，清单不匹配会阻止启动；入口不会自行扩大权限。

## 两个助手如何配合

| 助手 | 可以使用的工具 |
|---|---|
| `yuanxingmu_coordinator` | 读取已登记资料、查看权限和操作对象，再用原生 `transfer_to_agent` 转交给执行助手。 |
| `yuanxingmu_executor` | 查看权限和操作对象、保存操作提案或邮件草稿；原工作已有自动范围时，还能申请发送消息、上传文本和提交表单。 |

转交只能从第一个助手到第二个助手，并单独占用一次工具批次，可以附带正常说明文字。角色分工不会建立新的宿主授权，两个助手共用原任务、资料限制和剩余额度。正常操作在原自动范围内可连续完成，不需要逐次点击批准。提案和邮件草稿仍要经过宿主复核；保存草稿不等于发出邮件。

模型给出的整批工具名、参数和角色必须全部符合固定声明，才能开始执行。不能把任意终端、即时 `send`、宿主审批工具或其他转交目标混入调用。目标、内容、额度等检查在每项真实操作前进行；后面的操作被拒绝时，前面的合法操作可能已完成。

ADK 原生会并发调度一批工具。接入层按照模型回复中的原顺序执行宿主调用，并在结果不确定或执行出错时停止后续调用。普通的范围或额度拒绝可以交给模型处理，任务暂停、撤销、通信故障、存储错误及未确认结果会停止任务。

## 暂停和恢复

同名会话加 `--resume` 恢复。未完成任务必须沿用原任务文本。已完成会话遇到相同文本时，先向宿主核验全部已保存模型回复及工具结果，再返回保存的答案；宿主重新检查回答，不再请求工作模型生成或执行业务操作。完成后换成新文本可以继续对话，历史记录仍须逐条核验，权限和额度来自原任务。

ADK 2.9.0 的原生恢复有一个实际观察到的限制：同批第一个工具已生效、第二个工具抛错时，原生会话可能没有保存整批工具回复，直接恢复可能结束执行而漏掉剩余工具。因此，本入口为中断任务保存当前轮之前的原生会话，再通过真实 `Runner` 重放这一轮。

重放使用宿主保存的原模型回复、调用编号和工具结果，并重新检查当前权限。工具结果由宿主直接从 Broker 取得，绑定原会话、原模型调用编号和严格参数，写入 Agent 无法挂载的私有目录。Agent 不能提交一份结果让宿主认证。查询已保存模型回复使用独立的只读入口，记录缺失、结果未确认或当前防护拒绝时会失败，不会自动转为新的模型生成。

已确认的操作通过原编号查询结果；提案和草稿查询当前状态，不重新提交。原来的工具返回值用于重建对话，当前权限或未确认状态单独决定能否继续。原生事件要与保留的失败记录一致，才能继续新操作。已拒绝调用不会因为重试而重新执行；工具结果未能持久保存时，后续工具派发停止。失败会话完整保留，不伪造成功工具回复。恢复可能再次读取登记资料以检查当前条件，但不会重新发送已有操作。

检查点包括原生 `Session`、`Event`、模型请求和工具记录。原生事件的内容、作者、转交目标、调用编号、路径及动作都参加核对；只有明确不稳定的事件 UUID、时间戳和会话更新时间不用于比较。未知字段、被改写的记录、换任务或换用户身份不能直接用于恢复。检查点可能含对话和资料正文，应作为工作数据保存。

单个会话最多保存 128 条模型回复、128 条宿主工具结果、768 个原生事件和 16 次中断尝试。模型与工具私有存储分别限制为 64 MiB，单条最多 2 MiB；Unix 工具消息上限为 1 MiB。达到限制会拒绝继续，不会静默丢弃历史。恢复时宿主原件必须仍存在；旧开发版本中缺少工具原件的会话不能直接升级恢复。

## 验证与范围

首次 [GLM‑5.2 真实任务](evidence/google-adk-runtime-2026-09-13/REPORT.zh-CN.md)完成原生转交以及消息、上传、表单各一次；重开没有重复提交，撤销后拒绝继续。原模型回复、原工具结果和原生记录逐条核验，宿主原件在重开前后没有变化。同一冻结源码的 19 个 SDK 相关模块在 Linux 上 277/277 通过、零跳过，其中 ADK 专用测试 53 项。报告同时记录审查请求开销和面向普通用户的文案限制。

专用测试使用实际 ADK、Unix Broker 和本机接收端，模型服务为确定性测试服务。真实模型的任务结果与这些故障测试分开记录。

```bash
PYTHONPATH=.:tests ~/yuanxingmu-google-adk/bin/python -m unittest \
  tests.test_google_adk_runtime \
  tests.test_google_adk_runtime_automatic \
  tests.test_google_adk_runtime_faults -v
```

这个入口覆盖固定 `App`、`Runner`、两个 `LlmAgent`、单向转交及登记工具。任意已有应用、自定义工具、MCP、动态或并行多助手、远程会话服务、媒体、流式响应和五层攻击整体验收仍在范围之外。原生工具适配可以单独使用，但仅注册工具不会启用整个进程的隔离。进程组 CPU、内存和工作目录磁盘总配额仍未实现。
