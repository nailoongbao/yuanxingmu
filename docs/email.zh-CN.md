# 让 AI 帮拟草稿，由你亲自拍板发送

让 AI 依据你提供的报价或业务资料起草正式邮件，完成后自动提交至元星木工作台。在最终发出前，由你逐项核对收件人、邮件主题与正文细节。**拍板权始终在人，仅保存草稿绝不会自动外发邮件。**

[观看邮件全流程实机演示](https://yh-l20.github.io/yuanxingmu/email-demo.html) · [快速上手指南](https://yh-l20.github.io/yuanxingmu/start.html)

## 1. 配置发信邮箱，建立专属工作区

在支持邮件核验功能的工作台面板中，展开“发件邮箱设置”，依次填入发件地址、账号以及邮箱服务商提供的专属授权码（应用专用密码）。服务器地址与端口请严格对照服务商提供的“SMTP SSL/TLS”加密规范（通常为 465 端口）；当前版本聚焦于稳定链路，暂不启用 STARTTLS 模式。填写完毕后点击“保存发件邮箱”即可——保存配置只是登记信道，绝不会触发任何外发操作。

挑选好底座大模型、导入业务资料，创建一项全新的工作。**需要特别注意的是：早期历史任务不会自动静默追加邮件功能**；建议保留原任务档案，直接在新版工作台中创建新任务来体验邮件审核闭环。

你的发信凭证（授权码）将严格隔离保存在本机当前用户的私有配置中，其他系统用户无权读取；工作台绝不会把高敏感的密码写入浏览器前端缓存，更绝不会暴露给沙箱中的 AI 运行环境。

## 2. 吩咐 AI 生成草稿并递交工作台

进入该任务对应的 OpenClaw / Hermes 聊天会话，清晰告诉 AI 你的意图、发信背景与目标地址。例如（请将占位符替换为真实邮箱）：

> 请阅读我刚才导入的报价单，为【客户邮箱地址】拟一封专业的商务报价说明邮件。清晰列明各项分项费用及需要对方重点确认的交期节点；写好后请将完整草稿递交至工作台，等我逐字核对后再做发送。

随后切回工作台，在对应的工作卡片里点击“查看邮件草稿”。**请切记：AI 在聊天气泡里回复文字，并不代表草稿已经安全入库落盘；一切状态以工作台中的结构化草稿清单为准。**

## 3. 逐字核验细节，按需自由润色

点击“核对邮件”面板，认真核对发件人、收件地址、主题和正文全文。特别是金额数字、排期节点以及商务承诺等关键条款，务必仔细把关。

若觉得措辞欠妥或信息有误，直接点击“编辑草稿”即可。收件人、标题乃至正文所有字句均支持任意修改。修改完成后点击“保存修改”，系统会重新渲染供你复核；单纯点击保存不会导致邮件误发。如果你在此期间更换了全局发信邮箱配置，也建议重新核对当前草稿。

若评估后判定无需发送，直接选择“弃用草稿”。一旦确认弃用，该草稿将永久作废锁定，杜绝任何误触可能。

## 4. 人工明确授权，实时追踪送达状态

仔细检查无误后，手动勾选“我已核对发件人、收件人、主题和全文”复选框，最后郑重点击“确认发送这封邮件”。**必须强调：本次点击仅代表对眼前这一封特定邮件的单次放行，绝不等于给予了 AI 永久、自动发信的特权；后续产生的新草稿依然必须走完整的人工审核链路。**

| 工作台状态标识 | 背后含义与建议操作 |
| --- | --- |
| **待核对** | 邮件仍在本地草稿箱静默等待，你可以从容核对、自由编辑或随时弃用。 |
| **发送中** | 系统正在通过加密通道向邮件服务器握手提交，请稍候；此时随手关闭浏览器窗口不会中断发送任务。 |
| **已提交邮箱服务** | 邮件已成功交付至 SMTP 邮件服务器。**请注意：这代表服务商已接收，并不绝对等于已经躺在对方收件箱中，更不能推断对方已拆阅。** |
| **结果不明** | 网络抖动或超时，暂时无法确认服务器是否完整收录。此时建议先登录网页版邮箱查看“已发邮件”；若无记录也勿急躁，必要时向收件人求证。在状态明朗前请勿重复提交或催促 AI 重写，系统杜绝未经确认的盲目重试。 |
| **尚未开始发送** | 本次尝试由于配置异常等原因未实际启动。请检查发件参数后让 AI 重新提交一份新草稿再做审核；旧记录将原样留档不可再次调用。 |
| **已弃用** | 该草稿已被人工判定废弃，永久锁定禁发。 |

## 即使让 AI 暂时休眠，待审草稿依然安然无恙

在工作卡片中点击“暂时关闭”，待系统确认沙箱平稳退出后，你依然可以随时打开工作台查看、润色并批准先前的待审草稿，无需为了发一封邮件而特地重新拉起繁重的 AI 模型环境。请注意：仅关闭浏览器标签页并不会自动杀掉后台的 AI 计算进程。

点击“永久收回权限”则会强行冻结该任务后续发送所有待审草稿的能力，但已有的历史审计凭证仍完整可查。这项操作无法“时光倒流”去撤回网络上已经发出的邮件；如果底层通信已经启动，关闭窗口或收回权限同样不能阻止已交付的数据流。

## 当前版本的工程边界说明

为了确保安全审计的纯粹与可控，当前版本每封邮件仅支持**单一收件人与纯文本内容**，暂未引入抄送 (CC)、密送 (BCC) 以及复杂的富文本或附件解析。邮件主题上限为 200 字符，正文容量上限为 64 KB；所使用的邮件服务商必须支持标准的 SSL/TLS 加密发信协议。

官方演示基于 **OpenClaw 2026.9.4 搭配本地量化的 Qwen3-4B 开源模型** 录制，资料使用脱敏合成的商务报价，交付终点则是跑在本机上的加密回环测试服务。该测试端点绝不向外部互联网转发任何流量，因此演示既未向真实公网地址泄漏隐私，也不拿人工合成的受控场景宣称通用生产防御率。在实际部署中，你所对接的商业大模型依然会在 API 请求中看到你的提示词与上下文资料；若选用云端大模型服务，数据将遵循相应厂商的隐私规范。
