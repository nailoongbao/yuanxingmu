# 技能规则开关与用途对照 · 2026-09-12

本轮补齐两个经玄甲源码核实的功能：独立技能规则开关，以及把所选技能的用途说明与所属文件内容一起检查。没有运行真实模型、官方 Agent 或危险候选命令；裁判回答均为本机 HTTP 测试服务的预设数据。

## 实现与边界

- 新开关 `skill_rules_enabled` 默认为开启，由 `skill_rules_v1` 标识。工作台、CLI、主机实时入口、设置差异记录、推荐值恢复及创建时设置恢复均已接入。
- 用途对照由 `skill_purpose_v1` 标识，随技能语义检查开关运行。每个显式选择的技能目录根部 `SKILL.md` 提供用途；其完整原文、路径、字节数和 SHA-256 与待检查文件一起送审。用途仍是不可信数据，不授予权限。
- 用途只来自同一次安全读取产生的内存快照。不会在模型调用之间重新打开说明文件，不使用目录外或另一个技能的说明；子目录同名文件不能重新定义归属。
- 没有说明、空白、只有标题或只有技能名时，不调用裁判来猜用途，结果为 `skill_purpose_missing`、需要核对、`complete=false`。其他语义上的含糊仍由检查模型判断；这里没有证明模型准确率。
- 关闭规则保留开启的语义检查，关闭语义保留开启的规则。两者都关闭仍安全读取文件；链接、非普通文件、超限或无效文本不会当作已扫描。实例的固定快照验证和实际只读挂载不受这些开关控制。
- 新版创建基线为版本 2。旧版版本 1 保持原字段集与原文件字节；旧 profile 拒绝新开关，仍可修改已有设置、恢复已有基线，且不会被标为支持用途对照。

比较对象固定为 `FIND-Lab/AgentWard@46309333bdfdbcf4701000c1dad85b33b4a0e7ef`。其 `foundation-scan.ts:348` 先分析技能元信息，`:463` 对照能力摘要检查文件；元星木本轮直接传同一快照里的完整根说明，不使用其他技能的说明或未经绑定的缓存摘要。
