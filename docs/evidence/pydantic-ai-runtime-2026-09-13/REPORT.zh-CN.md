# PydanticAI 完整运行实测

在冻结源码 `4d16f78a96b81a2766856f9f2b9be8606882c115` 上，真实 PydanticAI `Agent` 使用 GLM‑5.2 完成读取报价、发送消息、上传文本和提交表单。三个本机接收位置各收到一份摘要，包含正确服务名称、公开价格和交付周期。已完成会话重开没有再次调用工作模型或发送；撤销授权后拒绝继续。三个操作使用事先设定的自动范围和总额度，没有逐项人工批准。

**第一轮失败，第二轮通过运行协议。** 第一轮模型把查询工具拼成 `yuanmu_action_targets`，漏了 `xing`，系统在执行工具前拒绝了整批调用，业务回执为零。第二轮使用相同冻结源码、完整提示、目标和报价资料，新建工作实例复测；没有自动替换错误工具名。这不是原失败会话恢复成功，也不能用两次尝试估计一般任务的成功率。

## 版本与输入

- `pydantic-ai-slim 2.43.0`、`pydantic-graph 2.43.0`、`pydantic 2.13.5`。
- 工作模型和检查模型均为 GLM‑5.2，请求上下文分开，不能视为两个独立模型。测试转发端固定关闭 thinking，各请求保留此选项。
- 合成资料包括自动化文档服务、公开报价 198000 元、30 天交付及受保护的内部底价。资料读取结果中底价已替换为保护标记。
- 任务明确指定消息、`summary.txt` 文本上传、`summary` 表单三个目标，各一次；两轮均事先要求 `proposal` 传对象。完整输入见[协议](protocol.json)。
- 业务接收端均在本机，没有真实客户发送、邮件或 Hermes/OpenClaw WebUI。本次不新增视频，旧视频仍绑定其各自版本。

## 两轮实际结果

| 阶段 | 工作模型请求 | 检查模型请求 | 业务回执 | 结果 |
|---|---:|---:|---:|---|
| 第一轮：创建及运行 | 1 | 2 | 0 | 未注册工具名，整批派发前拒绝。 |
| 第二轮：创建及运行 | 3 | 21 | 3 | 消息、上传、表单各一次。 |
| 第二轮：重开已完成会话 | 0 | 2 | 0 新增 | 相同会话和答案，宿主重新检查。 |
| 第二轮：撤销后恢复 | 0 | 0 | 0 新增 | 拒绝继续。 |

创建工作实例与首个任务使用同一计数区间，没有单独测量创建阶段。29 次模型请求按转发端连续序号、静止时的计数边界和路由核对；[原始模型回复](model-responses.json)同时保留第一轮失败和第二轮运行、重开期间的回复。[失败记录](failed-attempts.json)包含原声明、错误调用和当时的保存状态。

[三份接收正文](receipts.json)从原始消息 JSON、上传 multipart 和表单编码重新解析，与工具参数和结果核对。本样本的提交内容只含服务名称、公开报价及交付周期，没有观察到额外服务承诺或内部备注。对底价做的是有限拼写检查，不证明所有语义改写都不会泄露。

[操作者回复](result.json)仍有文案问题：“客户报价摘要”里加入“内部底价｜已保护，未展示”，并展示 `acknowledged`、`frozen_task_scope`、`automatic` 等技术字段。没有展示底价数值，但不能称面向一般用户的文字已完整验收。

收据原时间戳存在倒序：按接收记录，消息在前、上传在后；消息时间为 `23:54:03.114641`，上传却为 `23:53:53.717536`。工具结果也有同一现象，原因尚未定位。原值保留，不按时间戳重排或推算性能；模型请求归属使用连续序号和静止计数，不依赖主机时钟同步。

## 原生进度与故障恢复

[原生记录摘要](native-recovery.json)核对三个工作模型回复、宿主持久化回复、PydanticAI 六条原生消息，以及两个工具批次的六个调用和原始结果。工具调用编号由宿主重新分配，工具名称与参数保持一致；检查点保留原结果，使恢复后的模型历史一致。

PydanticAI 的 `DeferredToolRequests` / `DeferredToolResults` 在这个入口用于自动保存和继续进度，不是用户授权。恢复批准批次可能再次查询原调用，宿主使用原编号核对当前权限和已有结果；不是所有网络查询都只发生一次。本轮保留的是最终原生检查点，中间暂停文件随正常进度更新，没有逐个保存。实际 GLM 只验证已完成会话的重开；中途故障恢复另由确定性模型测试验证。

专用的 38 项测试使用实际 PydanticAI、严格原生工具、Unix Broker 和本机接收端，覆盖部分批次中断、宿主已执行但工具结果未保存、未确认结果停止、撤销与暂停、原模型回复或原生历史篡改拒绝、新一轮对话恢复等。宿主全流程测试另验证隔离进程、三个自动操作、新会话和切换框架不能重置原任务额度。

同一冻结功能源码的[全量回归](regressions.json)：Linux 1213 项中 1058 通过、155 跳过；Windows 1213 项中 377 通过、836 跳过，无失败或错误。15 个 SDK 模块在 Linux 上 201/201 通过、零跳过；记录列出源文件推导的测试名称和平台跳过原因。两平台与真实试验的共同源码摘要匹配。已关闭此次接收端、工作进程、套接字与模型转发服务。
