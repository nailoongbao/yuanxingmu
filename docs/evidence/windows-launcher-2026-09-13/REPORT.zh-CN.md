# Windows 启动器：验证范围与结果

这个入口用于打开已有 WSL 中由安装器 `0.4.0a2` 准备的元星木 `0.7.0a2`。它复用原来的 Linux 启动入口，保留安装、权限、版本、隔离及重复启动检查。没有修改已发布安装包，也没有新增 Windows 原生沙箱、WSL 安装或离线镜像功能。

## 实际 Windows→WSL 检查

在 Windows x64、已有 Ubuntu WSL 的专用合成验收安装中，通过与 GUI 相同的 `LauncherCore` 和嵌入桥接资源完成 29 项检查，全部通过；[原始结果](native-acceptance.json)仅记录判定，不记录管理链接或令牌。

- 实际 `wsl.exe` 发行版读取及参数往返，覆盖中文、空格、尾随空格、引号、反斜线和命令形似文字；没有把这些参数拼入 shell 命令。
- 从 Windows 启动真实 a2 工作台，并通过带授权的本机 HTTP 请求确认可用。
- 重复启动被原安装锁拒绝，已有实例仍可访问。
- 正常停止后服务不可连接；再次打开成功，管理令牌更新，旧令牌返回 HTTP 401。
- 缺失的安装目录被拒绝，未创建替代安装。

检查没有调用模型，也没有发送外部消息。运行中 AI 的暂停/关闭沿用网页操作；关闭本次管理入口不等于停止所有 AI 工作。

## 独立代码与组件检查

- C# 离线检查 50 项通过，包含真实 Windows 进程参数往返、严格 URL/协议解析，以及大量非法 UTF-8 输出后的原始管道排空。
- Python 桥接在 Linux 的 19 项检查通过；在 Windows 上 6 项通过、13 项 POSIX 检查明确跳过。包含 stdin EOF、显式停止、慢清理及外部哨兵不受影响。
- GUI 组件检查 8 项通过：保留用户输入路径原文；清理期间点击关闭保留关窗意图；清理完成后退出。另对实际 WinForms 控件绘制结果进行了视觉核对。
- 开发产物带 `-dev` 标记，未提交的输入不能生成可发布产物；正式构建逐个核对 Git blob 和编译前后源码哈希。

本轮发现并修正了 WSL 顶层选项被多余引号包裹、非法输出管道未完全排空、目录尾随空格被裁掉，以及清理中关窗意图丢失四项问题。失败的开发记录在本地保留，没有替换成成功结果。

## 范围限制

这次没有重跑首次安装和所有 Agent 防御场景，也没有单独完成默认浏览器的完整人工点击验收。GUI 会使用 Windows 默认浏览器打开经严格校验的本机地址；浏览器关联失败时显示可重试提示。程序没有 Authenticode 签名，请从对应发行页核对程序与清单的 SHA256。

源码文件哈希与验证环境见 [验收绑定](acceptance-bindings.json)。发行包的 `launcher-manifest.json` 另外绑定实际构建提交、编译器及全部输入文件。
